# 课表空白格交互 + 学期/作息多级设置(设计与改动说明)

本次改动围绕三块:① 空白格点击;② 设置页多级菜单;③ 作息方案数据结构化。
沿用现有视觉语言(Material 3 + 现有卡片圆角/配色),不引入新依赖。

---

## 一、页面层级

```
课表(Timetable)
 └─ 点击空白格
     ├─ 学期+作息均有效  →  添加课程(CourseEdit,预填 星期/开始节次/当前周)
     └─ 任一无效          →  「先完成课表设置」引导面板
            ├─ 学期         → 学期与作息 → 当前学期
            ├─ 作息时间     → 学期与作息 → 当前作息
            └─ 「继续添加课程」(两项都完成后可用)→ 回到原点击位置 → 添加课程

设置(Settings 首页)
 ├─ 学期与作息          →  学期与作息总览(两张摘要卡片)
 │                           ├─ 当前学期 → 学期菜单
 │                           │     ├─ 选择已有学期(单选 + 「当前使用」标记,确认才切换)
 │                           │     ├─ 新建学期(名称/日期选择器/总周数 + 折叠「按当前周推算」)
 │                           │     └─ 编辑当前学期(同上)
 │                           └─ 当前作息 → 作息菜单
 │                                 ├─ 选择作息方案(分组:内置模板 / 我的方案;选中→预览→「使用此方案」)
 │                                 ├─ 新建作息方案(从模板复制 / 手动填写 / 文本导入→预览→确认)
 │                                 └─ 编辑当前方案(内置模板编辑时自动复制为自定义方案)
 ├─ 数据管理(备份 / 恢复 / 清空)
 ├─ 桌面小组件(今日 / 周课表)
 └─ 关于
```

总览页的两张卡片只显示**摘要 + 状态徽标**,不在同一页展开表单。

### 引导流程中的点击位置

点击空白格但学期/作息未完成时,引导面板会**保留点击位置**:

- 点「学期」或「作息时间」进入设置 → 只把面板**临时隐藏**(`ScheduleGuide.hidden = true`),
  `target` 不清空;
- 从设置页返回(ON_RESUME)→ 重新核对状态并让面板重新出现;
- 两项都完成后由用户点「继续添加课程」→ 按原位置打开课程编辑页(不自动建课);
- 只有点「稍后再说」才真正丢弃点击位置。

## 二、数据结构改动

### 1. 新增「作息方案」概念(替代「删光再写模板」)

| 表/字段 | 说明 |
| --- | --- |
| 新表 `time_schemes` | `id, name, kind(0=内置模板 / 1=自定义), season, createTime` |
| `time_slots` 新增 `schemeId` | 归属方案;`0` = **原有作息**(升级前的全局节次,不对应 `time_schemes` 行) |
| `semesters` 新增 `schemeId` | 该学期使用的作息方案;`0` = 原有作息 |

- `schemeId = 0` 作为「原有作息」保留 id,自增主键从 1 开始,不冲突。
- 内置模板(夏季/冬季)在首次进入设置时**幂等**写入 `time_schemes` 并生成规范节次。
- 选择方案 = 只切换学期与节次的 `schemeId` 绑定,**不删除任何方案**,原自定义方案仍可再次选择。
- 同一方案可被多个学期引用;删除方案前查引用,受影响的学期回落到「原有作息」,其节次回落到 0 号桶,不产生孤儿行。
- 编辑内置模板 → 先复制为自定义方案(copy-on-write),模板本身与其他学期不受影响。
- 每套节次的写入/替换都在 `database.withTransaction { ... }` 内完成(DAO 层 `replaceScheme` 也标注 `@Transaction`)。

### 2. 数据库迁移

- `version 2 → 3`,`MIGRATION_2_3` 只做 `CREATE TABLE time_schemes` + 两个 `ADD COLUMN ... DEFAULT 0`:
  **不删除、不改写任何既有行**。
- 因此升级后:所有课程、学期、时间数据原样保留;已有学期自动关联 `schemeId = 0`(原有作息),
  不会被重新标记为「未设置」。

### 3. 备份格式

- `backupVersion = 2`;新增 `schemes` / `schemeSlots`。
- **v1 兼容字段 `timeSlots` 只放「原有作息」(schemeId = 0)的节次**,不再把所有方案的节次合并在一起
  ——合并后不同方案都会出现「第1节」,单套校验会误报「编号重复」。
- 导入分两条校验路径:
  - v1 备份(`backupVersion == 1`)→ 沿用 `TimeSlotParser` 的单套校验;
  - v2 备份 → **逐方案**用 `ScheduleStatus.isSlotsValid` 校验,「原有作息」桶单独校验。
- `backupVersion` 的默认值是 `LEGACY_VERSION(=1)`,导出时用 `encodeDefaults = true` 显式写入 2;
  这样缺少该字段的旧文件才能正确落到 v1 分支(否则会被误判为 v2)。
- 导入接受 `1..2`;旧版(v1)按「原有作息」恢复,行为不变(仅替换 0 号桶)。
- **完整恢复(第二轮复查修复)**:导入不再只读当前学期,而是按备份重建**全部学期与课程**:
  - **先清空本机全部自定义方案及其节次**(内置模板与「原有作息」保留),避免重复恢复累积出多份同名方案;
  - 补齐内置模板并把备份方案映射到本地新方案 id(内置模板按名称复用,不产生重复副本);
  - 清空本机学期与课程,按 `semesters` 逐条插入,并把 `schemeId` 映射到本地方案(找不到则回落 0);
  - 课程按原 `semesterId` 映射到新插入的学期 id(`BackupRestorePlanner` 纯逻辑计划器负责换算,可单测);
  - 当前学期取备份中标记的那个;恢复后刷新课表与桌面小组件;
  - 提示的数量为**实际写入的课程总数**(全部学期),不是备份中当前学期的条数。
  - 仅课程 JSON(旧格式)仍只替换当前学期课程,行为不变。

### 4. 删除方案的语义(不污染「原有作息」)

- 删除自定义方案前先查引用:
  - **无学期引用** → 直接删除方案与其节次;
  - **有学期引用** → 必须在弹窗中选择一个替代方案,这些学期改绑到替代方案后,再删除本方案及其节次。
- 被删方案的节次**直接删除**,不再 `reparentToLegacy` 并入 0 号桶
  ——那会产生重复的「第1节」并影响其他使用「原有作息」的学期。
- 内置模板与「原有作息」不可删除。

## 三、状态判定(绿勾/黄叹)

由 `util/ScheduleStatus.kt` **按已保存数据实时计算**,与是否进入过页面无关。

**学期「已完成」** = 已选定当前学期 && 名称非空 && 开学日期有效(`>0`)&& 总周数 ∈ `1..53`。

**作息「已完成」** = 当前学期已关联方案 && 至少一个节次 && 节次编号为正且不重复 &&
每节结束晚于开始 && 按编号排序后无重叠/倒序 && 覆盖当前学期课程用到的节次。

**不会**因为「未到开学日期 / 已放假 / 暂时没有课程」而显示待设置。
徽标 = 图标 + 文字(`已完成` / `待设置`),带 `contentDescription` 供无障碍朗读;绿/琥珀色固定色值,深色模式可读。

缺少节次时会明确指出缺哪些(如「缺少节次:第 9、10 节」),并引导修复。
